# Storytelling and Layout Rules

## Common page sequence

1. Hero
2. Compact metadata strip
3. Business Challenge
4. First analytical visual
5. Research / Analysis
6. Key Insights
7. Main framework / journey / funnel
8. Strategic Recommendation
9. Implementation logic
10. My Contribution
11. Outcome
12. GitHub link + Previous/Next project

## Hero
Each hero should contain:

- project type;
- project title;
- one-sentence summary;
- 4–6 skill tags;
- one strong visual.

The hero must not be mostly empty space.

## Metadata strip
Do not use a large white box with long paragraphs. Use a compact, scan-friendly strip.

## Key Insights
Present insights as a strong visual unit.

Recommended format:

- large numbering (01, 02, 03, 04);
- one primary insight visually dominant;
- 2–4 shorter supporting insights.

## Strategic Recommendation section
Use a stronger background treatment or stronger hierarchy using the existing site palette.

The section should include:

- one headline statement;
- 3–5 supporting principles;
- one visual showing the logic from problem to recommendation.

## Outcome
Use accurate wording.

Do not present proposed KPIs, strategic recommendations, or frameworks as measured commercial results unless the project copy explicitly confirms measured results.
